## 任务 1：扫描配置能力

### 1.1 关键代码路径

| 代码位置 | 作用 |
|---|---|
| `complete_verifier/arguments.py:113-119` | `--complete_verifier` 定义：choices=["bab","mip","bab-refine","skip","auto","Customized"]，default="bab" |
| `complete_verifier/arguments.py:303-308` | `--bound_prop_method` 定义：choices 含 "crown","alpha-crown" 等，default="alpha-crown" |
| `complete_verifier/arguments.py:347-387` | alpha-CROWN 参数：iteration(100), lr_alpha(0.1), lr_decay(0.98) |
| `complete_verifier/arguments.py:120-122` | `enable_incomplete_verification`：默认 True，控制是否运行初始边界传播 |

### 1.2 验证流程控制点（abcrown.py）

```
abcrown.py 主循环 (每个样本):
  1. PGD 攻击 (如果 pgd_order != skip)        ← 由 attack.pgd_order 控制
  2. 不完整验证 (如果 enable_incomplete)        ← 由 enable_incomplete_verification 控制
     └─ incomplete_verifier() → "safe-incomplete" 或 "unknown"
  3. BaB 完整验证 (如果 NOT verified_success
                  AND complete_verifier != 'skip'  ← 关键行: abcrown.py:344
                  AND verified_status != 'unknown-mip')
```

### 1.3 结论：框架原生支持只运行不完整验证

**关键配置**: `general.complete_verifier: skip`

- 设置后，abcrown.py:344 的条件 `complete_verifier != 'skip'` 为 False → **BaB 阶段被跳过**
- 不完整验证（CROWN/alpha-CROWN 边界传播）**仍然运行**（因为 `enable_incomplete_verification` 默认为 True）
- Logger 正常输出 Summary，状态包括 `safe-incomplete` 和 `unknown`

### 1.4 已确认的配置字段

| YAML 路径 | 作用 | 本实验取值 |
|---|---|---|
| `general.complete_verifier` | 跳过 BaB | `skip` |
| `solver.bound_prop_method` | 选择 CROWN / alpha-CROWN | `crown` 或 `alpha-crown` |
| `solver.alpha-crown.iteration` | alpha-CROWN 优化迭代次数（默认 100） | 保持默认 |
| `solver.alpha-crown.lr_alpha` | alpha 学习率（默认 0.1） | 保持默认 |
| `attack.pgd_order` | 是否运行 PGD | `skip`（先保持干净对比） |
| `bab.timeout` | 每样本超时（Logger 需要） | 30s（与 M4 同预算） |

### 1.5 不需要填写的字段

- `bab.branching.*` — BaB 不运行，分支参数无意义（但配置系统不会报错）
- `solver.beta-crown.*` — beta-CROWN 仅在 BaB 中使用

## 任务 5：检查报告

### 5.1 当前是否支持只运行 incomplete verifier？

**支持。** 设置 `general.complete_verifier: skip` 即可。框架原生支持该模式（`arguments.py:114` choices 包含 "skip"，`abcrown.py:344` 检查该值决定是否进入 BaB）。

### 5.2 需要新增哪些 YAML？

**8 个 YAML**，放置在 `complete_verifier/exp_configs/course/m6_incomplete/`：
- `mnist_m6_crown_eps0.{01,02,03,05}.yaml` (4 个 CROWN)
- `mnist_m6_alphacrown_eps0.{01,02,03,05}.yaml` (4 个 alpha-CROWN)

### 5.3 需要新增哪些脚本？

| 文件 | 作用 |
|---|---|
| `项目书/scripts/run_m6_incomplete_compare.sh` | 批量运行 8 组实验 |
| `项目书/scripts/summarize_m6_incomplete_results.py` | 日志 → CSV 解析 |

### 5.4 预计如何与 M4/M5 对比？

| 对比维度 | 对比对 | 预期结论 |
|---|---|---|
| 不完整 vs 完整验证耗时 | M6 CROWN vs M4 kfsb | M6 均时远低于 M4 |
| 不完整 vs 完整验证精度 | M6 CROWN vs M4 kfsb | M6 VRA 低于 M4（不分支导致更多 unknown） |
| CROWN vs alpha-CROWN | M6 crown vs alphacrown | alpha-CROWN VRA 更高、耗时略多 |
| 不完整验证 + PGD 潜力 | M6 vs M5 | M5 通过 PGD+BaB 达到最优平衡 |

### 5.5 是否存在配置风险？

| 风险 | 等级 | 说明 |
|---|---|---|
| **不完整验证不产生 unsafe** | 低 | CROWN/alpha-CROWN 是边界传播方法，不会主动搜索反例。`unsafe_by_incomplete` 预计全为 0。PGD 不参与（`pgd_order: skip`），所以无法区分 safe 和 unknown 之间的 unsafe。这是方法本质决定的，不是 bug |
| **epsilon=0.03/0.05 大量 unknown** | 高 | 不完整验证不分支，高 ε 下大量样本无法直接判 safe。这是预期行为——正是需要 BaB 的场景。结果需要标注"unknown 不代表 unsafe" |
| **batch_size=1024 时 0.05 可能 OOM** | 中 | MNIST FCNN 模型小（260K 参数），1024 batch 应安全。若 OOM，降至 256 即可 |
| **alpha-CROWN α 参数与 M4 不完全一致** | 低 | M4 内部也使用 alpha-CROWN 做初始边界，参数一致。但 M4 在 BaB 阶段还会继续优化，M6 不会 |
| **未分片** | 低 | 不完整验证无 BaB 递归，内存和 CPU 占用稳定，不需要分片 |
