## 0. 一句话理解本项目

**本项目不是普通的分类准确率测试。**

我们训练了一个识别手写数字（MNIST）的神经网络，准确率很高——但这不够。我们要回答一个更严格的问题：**如果有人故意微调输入图片（比如给数字"7"加一层肉眼看不见的噪声），模型会不会把它判成"1"？**

于是，我们使用一个叫 **alpha-beta-CROWN** 的工具，用数学方法**严格证明**：在允许的扰动范围内，模型对于某个样本的分类结果**一定不会改变**。

这个项目不发明新算法，而是把 alpha-beta-CROWN 当作一个"验证工具箱"，对比不同的验证策略（不同的分支选择方式、不同的扰动半径），看哪种策略验证得又快又准。

**一句话总结**：用形式化方法证明"加了微小噪声的 MNIST 手写数字，模型判得对不对"——并比较哪种验证策略更好。

## 1. 项目背景：为什么要验证神经网络鲁棒性？

### 1.1 普通准确率够吗？

假设你训练了一个手写数字识别模型，在 10000 张测试图片上准确率达到 98%。听起来很好。

但问题在于："准确率 98%"只能说明这 10000 张图片上的表现。它不能回答：

> 对于每一张图片，如果把像素值稍微改一点点（比如 ±3 个灰度等级），模型的预测还会保持不变吗？

现实世界中，摄像头噪声、光线变化、JPEG 压缩——这些都可以看作对输入的小扰动。如果一张停车标志的图片因为角度变化就让自动驾驶系统认成了限速牌，后果会很严重。

### 1.2 对抗扰动是什么？

**对抗扰动** 就是有人**故意**给输入图片加一些微小的、人眼几乎无法察觉的改动，专门用来骗过模型。

举个例子：一张数字"7"的图片，在像素上添加精心设计的微小改动后，人看仍然是"7"，但模型可能以极高置信度判定为"1"。这就是对抗样本攻击。

### 1.3 "没攻击成功" ≠ "模型一定安全"

这是核心认知：

- **经验攻击**（如 PGD）能找到反例，证明模型不安全，但找不到反例≠证明安全（也许只是攻击方法不够强）。
- **形式化验证** 能数学证明"在所有允许的扰动变化下，模型分类一定不变"，这才是真正的安全保证。

两者的关系类比：**攻击者是侦探在找嫌疑人的不在场证明缺陷，验证者是数学家在用逻辑推理证明一个定理。**

### 1.4 为什么本课程项目关心这个问题？

这对应软件质量保障课程的核心主题：**从经验测试走向可证明的质量保证**。传统软件有单元测试、集成测试，但神经网络的行为不是程序员编写的，而是从数据学出来的——如何"测试"它变得更困难。鲁棒性形式化验证是当前解决这个问题的主流技术路线之一。

## 2. 核心验证问题：到底在证明什么？

### 2.1 自然语言描述

我们关心的核心问题是：

> 给定一张输入图片 x（比如说数字"7"），它的正确标签是 y，设定一个扰动半径 ε（比如每个像素最多变化 ε）。
>
> 我们要证明：**所有**与 x 的差距不超过 ε 的图片 x'，模型都会正确地判断为 y。
>
> 换言之：在这个小小的"ε-球"里，不存在任何一个让模型判断错误的输入。

### 2.2 形式化表达

对于输入样本 x、真实标签 y、扰动半径 ε（L∞ 范数）：

**希望证明**：对所有满足 ||x' - x||∞ ≤ ε 的 x'，都有：

$$f_y(x') > f_j(x'), \quad \forall j \neq y$$

其中 f_y(x') 是模型对真标签 y 的输出置信度。

### 2.3 L∞ 扰动是什么意思？

L∞ 范数约束意味着：**每个像素的值最多偏离原值 ε**。

例如，一张 MNIST 灰度图的像素值是 0~1 之间的实数。若 ε = 0.02，则每个像素最多可以上下浮动 0.02。一个 28×28 图片有 784 个像素，每个都可以独立变化——所以可能的输入空间非常大（784 维超立方体）。

### 2.4 ε 越大，验证越难

- ε = 0.01：扰动很小，几乎所有样本都能证明鲁棒。
- ε = 0.02：开始出现 timeout（无法在规定时间内证明）。
- ε = 0.03：大量样本 timeout，verified acc 明显下降。
- ε = 0.05：绝大多数样本 timeout，验证进入"超时主导"区域。

### 2.5 验证结果的三种状态

| 状态 | 含义 | 通俗解释 |
|------|------|----------|
| **safe / verified** | 证明鲁棒 | "这个人很清白——所有可能的变化都不会让他犯错" |
| **unsafe / violated** | 找到反例，不鲁棒 | "抓到证据了——有一个微调后的输入确实让他认错了" |
| **unknown / timeout** | 规定时间内无法判断 | "这个人嫌疑很大，但案子太复杂，审了太久还没定论" |

我们评价验证策略优劣的核心指标是 **Verified Accuracy（验证准确率）**：

$$\text{VRA} = \frac{\text{safe 样本数}}{\text{总样本数}} \times 100\%$$

另两个重要指标是 **timeout 数量**（少越好）和 **mean time**（平均验证耗时，低越好）。

## 3. 前置知识速览

### 3.1 ReLU 网络为什么适合形式化验证？

ReLU（Rectified Linear Unit）激活函数定义为 `max(0, x)`：输入为正就原样输出，输入为负就输出 0。这个函数是**分段线性**的——整个输入空间被切成许多线性区域，每个区域里网络行为就像一个简单的线性函数。

因为线性函数好分析、好算边界，验证工具就可以利用这个性质：对每个线性区域分别分析，再把区域的结果合起来。纯 ReLU 网络本质上就是一个个线性片段拼接而成的复杂函数——这让它可以被数学工具精确刻画。

### 3.2 PGD 攻击是什么？

PGD（Projected Gradient Descent）是一种**经验攻击**方法。它的思路很简单：

1. 从原始输入 x 开始。
2. 计算模型对当前输入的分类损失，求损失关于输入的**梯度**——即"往哪个方向改像素会让模型更容易犯错"。
3. 沿梯度方向走上一步，然后"投影"回允许的扰动范围内（确保扰动不超过 ε）。
4. 重复上述步骤若干次，最后看模型预测是否变了。

关键点：

- PGD 能找到反例 → **证明不鲁棒**（unsafe）。
- PGD 没找到反例 → **什么也证明不了**。可能模型确实鲁棒，也可能是 PGD 攻击不够强。
- 在本项目中，PGD 的攻击强度由 `pgd_steps`（迭代步数）和 `pgd_restarts`（重启次数）控制。

### 3.3 IBP / CROWN 是什么？

这两者都是**边界传播**方法（Bound Propagation），核心思想是：给定输入的范围，**逐层计算每一层输出的上下界**。

- **IBP（Interval Bound Propagation）**：用区间算术逐层传播。比如如果第一层输出范围是 [0.1, 0.5]，第二层就用这个区间算出输出。速度极快，但边界越来越松。
- **CROWN**：与 IBP 类似也是逐层传播，但使用**线性松弛**——把 ReLU 非线性函数用线性上下界包裹起来，然后通过闭式解高效传播。比 IBP 更紧（更精确），但仍是一种近似。

一句话区别：IBP 是"宽区间快速传播"，CROWN 是"线性松弛更紧传播"。两者都能在**不分支**的情况下给出快速判断，但 ε 大时容易 unknown。

### 3.4 alpha-CROWN 是什么？

CROWN 的线性松弛中使用了**固定斜率**的线性上下界来包裹 ReLU。alpha-CROWN 则把松弛中一些参数（α）设为**可优化变量**，通过梯度下降去调整它们，使得最终的输出边界最紧。

**类比**：CROWN 相当于用一个固定模具去套每个 ReLU 的形状；alpha-CROWN 相当于有一个可以调整松紧的活口模具，调紧后边界更精确。

alpha-CROWN 是**不完整验证**——不分支，一步算完，快但可能 unknown。

### 3.5 beta-CROWN 是什么？

当验证进入分支定界（BaB）阶段时，我们需要**把问题切成子问题**：把一个 ReLU 神经元"切分"——强制规定它是激活（>0）或非激活（≤0）。切分之后，每个子问题的输入空间变小了，边界应该更紧。

beta-CROWN 就是把这些"神经元已被切分"的信息编码到边界传播过程中。它在每个子问题内部用更紧的 β 约束代替原来的松弛，使子问题的边界比父问题明显收紧。

**alpha-CROWN 负责在无分支时把边界调紧，beta-CROWN 负责在分支后把子问题边界收紧。两者配合形成完整验证。**

### 3.6 Branch-and-Bound 是什么？

Branch-and-Bound（分支定界）的核心思想是"分而治之"：

1. 先对整个 ε-球做一次快速验证（CROWN / alpha-CROWN）。
2. 如果能直接判 safe，结束。
3. 如果不能，就选一个 ReLU 神经元，把它的不确定性"切开"（规定它一定是 >0 或 ≤0），把一个大区域分成两个小区域。
4. 在每个小区域里重新做边界传播（beta-CROWN）。
5. 如果一个子区域被证明 safe，就不再切它；如果被证明 unsafe，记录结果。
6. 反复切下去，直到所有子区域都判出结论，或超时。

**类比**：假设你要检查一栋教学楼是否"所有房间都安全"。你发现整个建筑太大无法直接判断——于是你逐层检查、逐房间检查，不断缩小范围。安全房间就标记为合格，有问题房间记录在案。如果有些房间锁着门看不到，那就 timeout 了。

### 3.7 kfsb 分支策略是什么？

BaB 中最关键的决策是：**每次选择哪个 ReLU 神经元来切？** 这个决策直接影响验证效率。

- 选得准 → 快速收紧边界，很快判出 safe/unsafe。
- 选得差 → 徒增计算量，仍然 unknown，最后超时。

**kfsb（K-FSB，K-Way Fast Split via Backward）** 是一种分支评分策略：

1. 先筛选若干候选神经元（candidates 参数决定取几个）。
2. 对每个候选神经元用 lookahead 方法估算"切分后边界能收紧多少"。
3. 选择评分最高的神经元作为切分点。

对比默认的 **babsr** 策略（简单按 ReLU 松弛的偏差打分），kfsb 在候选筛选和评分机制上更精细。

**这是本项目的主要改进方向**——把 babsr 换成 kfsb 并调节 candidates 参数。

## 4. 本项目使用的工具：alpha-beta-CROWN

### 4.1 它是什么？

[alpha-beta-CROWN](https://github.com/Verified-Intelligence/alpha-beta-CROWN) 是一个开源的神经网络鲁棒性验证器，在国际验证竞赛 VNN-COMP 中多次获得第一名。它整合了 CROWN 线性松弛、alpha-CROWN 边界优化、beta-CROWN 分支约束传播以及 GPU 加速，可以在单个框架内完成不完整验证和完整验证。

### 4.2 它支持哪些验证路线？

| 验证路线 | 在 alpha-beta-CROWN 中的对应 | 本项目的使用 |
|----------|------------------------------|------------|
| PGD 攻击 | `attack/attack_pgd.py`，配置 `attack.pgd_order: before` | M5 已完成 ✅ |
| CROWN 不完整验证 | `incomplete_verifier_func.py`，仅边界传播不分支 | M6 已完成 ✅ |
| alpha-CROWN 不完整验证 | 同上，加 alpha 可优化参数 | M6 已完成 ✅ |
| beta-CROWN + BaB 完整验证 | `bab.py`，完整 BaB 循环 | M2/M3/M4 已完成 |
| 分支策略对比 | `heuristics/`（babsr, kfsb, fsb, auto） | 核心研究变量 |
| LP/MIP 可选精化 | `lp_mip_solver/`，需 Gurobi 许可证 | 当前未使用 |

### 4.3 为什么选择 alpha-beta-CROWN 而不是 Marabou？

| 维度 | alpha-beta-CROWN | Marabou |
|------|------------------|---------|
| 方法路线 | 线性松弛 + BaB | SMT/SAT 求解 |
| GPU 加速 | 支持，速度优势显著 | 主要靠 CPU |
| 配置灵活性 | YAML 配置 + CLI，易于批量实验 | 需要自定义输入格式 |
| 课程适配度 | 可在有限时间完成多组对比 | 单个样本耗时可能更长 |
| 学习曲线 | 配置级使用，不要求深入源码 | 需要理解 SMT 编码 |

**本项目以 alpha-beta-CROWN 为主实验平台**。Marabou 作为 SMT/Solver 路线的方法学对照，在报告中会提及以展现技术全面性，但不在课程周期内作为主实验平台。

## 6. 当前模型与数据集

### 6.1 主要验证模型：MNIST FCNN

```
输入: 28×28 灰度图 (784 维，每个像素值 0~1)
结构:
  Flatten (784 → 784)
  → Linear (784 → 256) → ReLU
  → Linear (256 → 128) → ReLU
  → Linear (128 → 10)
输出: 10 个类别的 logits
参数量: ~260K
Clean Accuracy: ~99%
```

**为什么适合作为形式化验证实验对象？**

1. **纯 ReLU 激活**：分段线性，边界传播方法可以直接分析。

4. **输入维度适中**：784 维，不是"维数灾难"级别。

## 9. M5：PGD 攻击评估 ✅ 已完成

### 9.1 为什么要补 PGD？

在 M2/M3/M4 的所有实验中，`attack.pgd_order` 均设置为 `skip`——即完全跳过了 PGD 攻击步骤。这带来两个问题：

1. **缺少攻击 vs 验证的对比**：没有实验数据回答"PGD 能找到多少反例、BaB 又能证明多少安全样本"。
2. **缺少预筛效率分析**：如果 PGD 能快速筛出一批 unsafe-pgd 样本，后续 BaB 就不需要在这些样本上浪费计算资源。

### 9.2 PGD 和形式化验证的区别

| 维度 | PGD 攻击 | BaB 形式化验证 |
|------|---------|--------------|
| 能证明 unsafe？ | 能（找到反例） | 能（分支过程可能发现反例） |
| 能证明 safe？ | **不能** | **能**（所有子问题均证明安全） |
| 速度 | 快（秒级） | 慢（分钟级，含超时风险） |
| 角色 | 预筛/测试工具 | 最终证明工具 |

### 9.3 M5 实验设计

**核心变量**：`attack.pgd_order: before`

含义：在 BaB 分支定界之前，先对每个样本运行 PGD 攻击。如果 PGD 成功找到对抗样本 → 标记为 "unsafe-pgd"，该样本不再进入 BaB。如果 PGD 没找到 → 继续进行 BaB 验证。

**PGD 参数**：`pgd_steps: 100`，`pgd_restarts: 30`，`attack.pgd_order: before`

### 9.6 M5 核心结论

1. **PGD 反例检测能力随 ε 增大显著增强**：ε=0.01→0→0.05，pgd_unsafe 从 0 增至 58（0%→58%）。
2. **PGD-before 大幅降低 timeout**：ε=0.05 时 timeout 从 89（M4 无 PGD）降至 31（M5 有 PGD），降幅 65.2%。PGD 以秒级代价提前判定反例，避免了 BaB 在这些样本上的无效搜索。
3. **所有 falsified 样本均由 PGD 发现**（bab_unsafe_count 全为 0）：当前 PGD 参数（100 steps × 30 restarts）已足够覆盖 BaB 可检测的全部反例。
4. **安全证明仍依赖 BaB**：PGD 找不到反例不代表安全——ε=0.02 时 PGD 仅发现 5 个反例，剩余 95 个样本中 BaB 证明了 92 个 safe。最终安全保证来自形式化验证。
5. **公平性说明**：ε=0.03 和 ε=0.05 采用分片降压（timeout=12s），与 M4 的 timeout 预算不完全一致，高 ε 对比主要用于工程趋势分析。ε=0.03 已补跑 M5-control 公平对照（timeout=30s），结论以对照为准。

### 9.7 可写入最终课程报告的三条结论

> 以下三条可直接用于课程报告"M5 实验结果"小节：

**结论 1：PGD 反例检测能力随 ε 增大显著增强。**
ε=0.01 时 PGD 未找到任何反例；ε=0.02 时检测到 5 个（5%）；ε=0.05 时检测到 58 个（58%）。PGD 在高扰动下可作为高效的 unsafe 样本预筛工具。
——证据：`项目书/results/m5_pgd/m5_pgd_compare.csv`，pgd_unsafe_count 列。

**结论 2：PGD-before 预筛选可大幅降低 BaB 的 timeout 和平均验证时间。**
在 ε=0.03 公平对照中，PGD 预筛使 timeout 从 32 降至 10（降幅 68.8%），VRA 从 68% 提升至 73%（+5.0pp）；在 ε=0.05 中 timeout 从 89 降至 31（降幅 65.2%）。PGD 以秒级代价提前判定反例，避免了 BaB 在这些样本上长达数十秒的无效搜索。
——证据：M5-control 与 M4 对比表；`项目书/results/m5_pgd_control/m5_pgd_control.csv`。

**结论 3：PGD 找不到反例不代表安全，最终安全证明仍依赖形式化验证。**
在全部 4 个 ε 下，bab_unsafe_count 均为 0——PGD 找到了全部可检测的反例。但 ε=0.01 时 PGD 未找到任何反例，而 BaB 证明全部 100 个样本确实安全；ε=0.02 时 PGD 仅找到 5 个反例，剩余 95 个中 BaB 证明 92 个安全、3 个超时。**安全保证来自 BaB 的数学证明，而非 PGD 的"未找到"。**
——证据：`项目书/results/m5_pgd/m5_pgd_compare.csv`，bab_safe_count 与 bab_unsafe_count 列。

**详细报告**：`项目书/results/m5_pgd/M5_PGD攻击评估结果报告.md`

## 10. 当前主要改进点：kfsb_candidates5

### 10.1 改进本质

**改进不是什么**：不是改算法原理（CROWN/BaB 框架不变），不是改模型结构。

**改进是什么**：优化 BaB 中"选择哪个 ReLU 神经元来切分"这个决策。这就像：

> BaB 就像排查一栋大楼的安全隐患（检查每个房间是否有问题）。默认的 babsr 策略按"哪个区域看起来最可疑"的简单规则决定先去哪个房间。kfsb 则更聪明：它先列出几个嫌疑最大的房间（candidates），然后每个都快速探查一下（lookahead），再选最可能"一刀解决问题"的那个。

如果选得好，边界快速收紧，很快就能证明 safe 或 unsafe；选得不好，切了很多次后仍然 unknown，最后导致超时。

### 10.2 改进前后对比

```
改进前 (baseline = babsr, ε=0.02):
  ┌──────────┐   简单评分    ┌──────────┐   边界收紧不够    ┌──────────┐
  │ 100 样本  │ ──────────→ │ 切 ReLU  │ ──────────────→ │ safety    │
  │          │   选一个切    │          │  很多轮仍不明确  │ 91% VRA  │
  └──────────┘              └──────────┘                 └──────────┘
                                                              ↑ 9 timeout

改进后 (kfsb_candidates5, ε=0.02):
  ┌──────────┐   筛5个候选   ┌──────────┐   边界更快收紧    ┌──────────┐
  │ 100 样本  │ ──────────→ │ lookahead│ ──────────────→ │ safety    │
  │          │  选最优一个   │ 估算效果  │                  │ 93% VRA  │
  └──────────┘              └──────────┘                  └──────────┘
                                                              ↑ 7 timeout
```

### 10.3 指标对比

| 指标 | baseline (babsr) | kfsb_candidates5 | 改善 |
|------|:---:|:---:|:---:|
| Verified Acc | 91.0% | **93.0%** | **+2.0%** |
| Timeout 数 | 9 | **7** | **-2** |
| Mean Time | 4.06s | **3.24s** | **-0.81s** |
| Max Time | 56.27s | **35.90s** | **-20.37s** |

### 10.4 为什么可以写入课程报告？

1. **有明确对照**：M3 消融实验完整对比了 method/candidates/reduceop 三个维度。
2. **有参数解释**：candidates=5 比 10 更好，说明在当前任务上适度筛选优于过宽候选。
3. **有趋势支撑**：M4 证实 kfsb 在 ε=0.01~0.03 区间持续优于 baseline 和 auto。
4. **符合课程要求**："提出改进的验证方法"——kfsb_candidates5 是验证策略层面的改进。

## 13. 答辩速讲版本（3 分钟）

> 以下是口语化的答辩讲稿，约 600 字，语速正常可在 2.5~3 分钟说完。

---

各位老师好，我们小组的课题是**神经网络鲁棒性形式化验证**。

**先讲问题是什么。**

我们知道，现在的 AI 模型在很多任务上准确率很高——比如我们训练的手写数字识别模型，准确率能到 99%。但这个 99% 只说明在这些测试图片上表现好。如果有人故意给输入加一点点噪声——人眼看完全一样——但模型可能就预测错了。这在实际应用中很危险。

所以我们问一个更严格的问题：**在允许的微小变化范围内，能不能数学上证明，模型一定不会判错？**

这个问题就叫局部鲁棒性验证。

**然后是方法。**

我们把整个问题交给一个叫 alpha-beta-CROWN 的验证工具。它做的事情可以这样理解：输入图片是一个点，允许变化的范围是以这个点为中心的一个小球。验证工具要证明这个小球里的所有点，模型都判对。如果球太大一次判不了，就把球切成更小的球，继续判——直到所有小球都判出"安全"或"不安全"的结论为止。这个"切球"的过程叫分支定界。

这里有一个关键问题：**每次应该先切哪个方向？**

我们对比了几种分支策略。默认策略叫 babsr——简单地说就是看哪个神经元最可疑就先切哪个。我们测试了另一种叫 kfsb 的策略，它更聪明：先挑出几个比较可疑的，快速估计一下切开后的效果，再选最好的那个切。

**结果发现**：kfsb 配上候选数=5，在 ε=0.02 的条件下，能把证明成功率从 91% 提到 93%，平均每个样本的验证时间也缩短了大约 20%。而且这个优势在不同扰动半径下都稳定。

**M5 补充了什么**：我们还补了 PGD 攻击评估。关键发现：PGD 找反例的能力随扰动半径增大急剧上升（ε=0.05 时 58%）；PGD 预筛选大幅降低 BaB 超时（ε=0.05 时 -65%）；但安全保证仍然来自形式化验证——PGD 找不到反例不代表安全。

**M6 补充了什么**：我们还评估了不完整验证（CROWN/α-CROWN，不分支不 BaB）。CROWN 速度极快（~0.2s/样本，比 BaB 快 49 倍）但 ε 大时 VRA 急剧下降（0.05 时仅 4%）；α-CROWN 更紧但耗时高 6~12 倍。这形成了一个完整验证能力光谱：CROWN(0.2s)→α-CROWN(1s)→BaB(6s)→PGD+BaB(4s)，从快到慢、从弱到强。

**一句话总结**：我们证明了一个实用的神经网络在某些输入扰动下是形式化安全的，并形成了一套从快到慢、从攻击到证明的完整验证策略对比链——不是从零发明，而是把顶尖工具用好、用对参数。
